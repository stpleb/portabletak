PortableTAK 2026.10.28.3 (test release): voice security fix on OpenMANET nodes, a voice watchdog, and node clocks set at sign-in.

**Security fix (OpenMANET nodes)**
- On a node the voice server's password and its control secret were empty: the node has no `od`, which made them. Without the password, anyone could join voice as a guest while the sign-in check was starting or stopped (the gap 2026.10.28.1 closed elsewhere). Both are now made with `hexdump` on nodes, and voice refuses to start if either is empty. Existing nodes get them on the next start.

**Voice**
- A watchdog starts again any voice part that stopped (voice server, sign-in check, recorder, talk group link), within 30 seconds, and notes it in the voice log.
- TAK PTT (plugin, installed separately): keeps trying to reconnect while the server's sign-in check is starting, instead of staying offline after a server restart.

**Node clock**
- An OpenMANET node has no clock that keeps time while it is off and usually no internet, so after a reboot its time can be hours off (voice history, logs). When the administrator signs in to the dashboard, a node more than 2 minutes off sets its clock from the browser, after the password checks out and before the session starts. Only on OpenMANET nodes.

**Tested:**
- On Node01 (OpenMANET node): voice secrets made and set; sign-in check killed, then the voice server and check together: back within 30 s, phone reconnected on its own; Node01's clock set from 7 h 28 min behind.
- New unit tests for the clock and the sign-in change; provision tests pass (Linux-only tests skipped on the Mac).
- Fresh-drive build test: 7 of 7 services.
