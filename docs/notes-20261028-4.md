PortableTAK 2026.10.28.4 (test release): the talk group link now reaches OpenMANET's own push to talk.

**OpenMANET talk groups**
- OpenMANET's own comms (a node's web page COMMS push to talk, and its audio modules) sends on multicast 239.192.41.1; the ManetNode plugin uses 239.41.0.1. The server's talk group link used only the second, so people on a node's web PTT and people on the server did not hear each other. The link now listens on and sends to both addresses, and a packet heard on both counts once.
- A node's own push to talk needs comms turned on in its OpenMANET settings (`comms: enable: true` in `/etc/openmanetd/config.yml`; `controlSource: web` for the web page). Browsers only allow the microphone on https pages: on a node, open https://10.41.250.10:8445 (PortableTAK serves the OpenMANET page there with the drive certificate) to talk from a phone browser.
- TAK PTT (plugin, installed separately) does the same: both addresses.

**Tested:**
- On Node01 with comms on: web PTT on CH 1 recorded in LOBBY ("OpenMANET CH 1", 9.5 s) and transcribed on a Samsung S22; the S22 talking in LOBBY heard on the node's web page.
- Server tests pass (13), including the new duplicate check.
- Fresh-drive build test: 7 of 7 services.
