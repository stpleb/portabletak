PortableTAK 2026.10.28.6 (test release): Data Sync missions with an official TAK Server, and a fix for deleting missions from a phone.

**Federation with an official TAK Server: Data Sync missions**
- Public missions now federate with an official TAK Server in both directions: creating a mission, adding and removing its files and map items, and deleting it. Phones on each side are told about the change.
- Missions with a password are not shared.
- Removals and deletes need `allowFederatedDelete="true"` on the TAK Server's `<federation>` in CoreConfig.xml, as well as `allowMissionFederation="true"` (already needed for data packages).
- Missions are still not shared between two PortableTAK servers; data packages and positions are.
- Changes made while the link is down are sent when it comes back.

**Fixes**
- Deleting a Data Sync mission from a phone failed with a server error (the mission's group links blocked the delete). It now works; the mission's files are kept.

**Guide**
- Section 14 describes mission sharing and the TAK Server settings it needs.

**Tested:**
- Against official TAK Server 5.8 (container), checked in both servers' databases: a mission created, given a file (with its bytes) and a map item, the item and file removed, and the mission deleted, from each side; nothing echoed back.
- Mission delete from a phone's API call on a test server: returns 200, mission gone, file kept.
- Unit tests: federation (42 passed, 2 skipped).
- Fresh-drive build test: 7 of 7 services.
- Not yet tested: real phones on both servers, a TAK Server that dials PortableTAK.
